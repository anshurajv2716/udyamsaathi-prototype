**Problem Statement Title:** AI-Driven Hyper-Local Business Advisory and Financial Structuring Assistant for Rural Micro-Entrepreneurs

## 1. Problem Statement

Rural micro-entrepreneurs and aspiring small business owners in India often lack access to:

- **Localized market intelligence** — data-driven guidance on which businesses are actually viable in their specific district or taluka, rather than generic advice that ignores local demand, competition and seasonality.
- **Structured financial planning** — a clear breakdown of how much capital a business needs, how to split it between fixed assets, working capital and emergency reserves, and how much of it can realistically come from a loan.
- **Awareness of applicable government schemes** — many are eligible for schemes like PM Mudra Yojana or NABARD-backed credit but don't know which one applies to their business or how to access it.
- **Guidance in their own language** — most existing advisory tools and government portals are English-only, which excludes a large share of the target population.

The result is that many rural entrepreneurs either don't start a business, start one that isn't locally viable, or under/over-borrow because they have no structured way to plan their capital.

## 2. Proposed Solution

**UdyamSaathi** ("business companion") is a web-based advisory tool that takes three inputs from an entrepreneur — their **district**, a **business sector** they're considering, and the **capital (margin money)** they currently have — and returns a complete, personalized advisory report covering:

1. Whether the sector is locally feasible, based on district-level demand, competition, seasonality and logistics data.
2. How to structure their available capital right now (fixed / working / reserve split).
3. What their full financial picture would look like *if* they also took a loan (sources & uses of funds).
4. A profitability outlook — a realistic expectation of when the business tends to stabilize.
5. The specific loan scheme, amount, interest rate, tenure and EMI schedule they're eligible for.
6. A plain-language narrative summary of the whole report, generated by an LLM, so the numbers are explained in context rather than left as a table.

The entire experience is available in **English, Hindi and Marathi**, since the target users are rural entrepreneurs who may not be comfortable reading financial advice in English.

This is a **decision-support tool**, not a lending platform — it doesn't disburse loans or connect to a bank. It helps a person walk into a bank or a scheme's local office already knowing what to ask for.

## 3. How It Works — User Flow

1. **Locate** — the user selects their district (and optionally a village/sub-location for context; scoring is done at district level).
2. **Business options** — the app shows every business sector for that district, ranked by a computed feasibility score, with the typical investment range for each.
3. **Capital input** — the user enters how much margin money they currently have available.
4. **Advisory report** — the app returns the full report described above, downloadable as PDF/PNG or emailed to the user.

## 4. Architecture

```
frontend/                React + TypeScript (Vite)
  src/
    screen/              One component per step of the user flow
      LocateScreen.tsx      -> district / sub-location input
      BuffetScreen.tsx      -> ranked business sector options
      CapitalScreen.tsx     -> capital input
      ReportScreen.tsx      -> full advisory report
    components/          Reusable UI (charts, language toggle, export menu, etc.)
    translations.ts      Central en/hi/mr dictionary for all static UI text
    api.ts                Talks to the FastAPI backend
    types.ts              Shared TypeScript types (mirrors backend response shapes)

backend/                 FastAPI (Python)
  main.py                 API entrypoint — exposes the engines over HTTP
  engines/
    feasibility_engine.py     Scores a sector's local viability for a district
    financial_engine.py       Builds the capital structuring + loan plan
    bootstrap_engine.py        Computes the capital split (fixed/working/reserve)
    profitability_outlook.py  Estimates stabilization window and outlook text
  llm/
    narrator.py           Turns the structured report into a plain-language narrative
  data/
    pune.json                  District-level sector data for Pune (Rural Talukas)
    ahmednagar.json             District-level sector data for Ahmednagar
    capital_structuring.json    Sector-wise capital split templates
```

### Engines

| Engine | Responsibility |
|---|---|
| `feasibility_engine.py` | Computes a 0–100 feasibility score per sector per district from demand, competition, seasonality and logistics factors; returns a recommendation band (High Potential / Moderate Potential / Caution) along with a strongest/weakest factor breakdown. |
| `bootstrap_engine.py` | Splits the entrepreneur's *current* capital into fixed capital, working capital and a rolling/emergency reserve, based on sector-specific ratios and itemized needs (e.g. equipment, raw material, buffer). |
| `financial_engine.py` | Scales the plan up to full project size, computes the loan amount, routes the entrepreneur to the correct scheme (Micro Finance Scheme / Term Loan Scheme), and generates the EMI/amortization schedule including any moratorium period. |
| `profitability_outlook.py` | Estimates a typical stabilization/breakeven window for the sector and produces an outlook note, with a disclaimer that this is a general pattern for the score band, not a prediction for that specific business. |
| `narrator.py` | Sends the structured report to an LLM (Gemini) to generate a short, plain-language narrative summary in the user's selected language, so the report reads as advice rather than a spreadsheet. |

### Frontend ↔ Backend contract

The frontend never hardcodes business logic or numbers — every score, capital split, loan figure and narrative comes from the backend's `AdvisoryResponse` (see `types.ts`). The frontend's `translations.ts` only translates *static labels* (headings, button text, sector names, scheme name labels); all *computed* content flows through from the backend for the language the user selected.

## 5. Current Coverage (Prototype Scope)

- **Districts:** Pune (Rural Talukas), Ahmednagar
- **Sectors:** Dairy, Poultry, Food Processing, Retail, Tailoring, Agri Input Retail
- **Languages:** English, Hindi (हिंदी), Marathi (मराठी)

Adding a new district only requires a new JSON file in `backend/data/` following the same schema — no frontend code change is needed. Districts shown in the UI are the ones listed in `frontend/src/types.ts` (`DISTRICTS`), which should be kept in sync with the data files available on the backend.

## 7. Running Locally

### Prerequisites

- Python 3.11+
- Node.js 18+
- A Gemini API key (for the narrative feature) and, optionally, a Resend API key (for the email-report feature)

### Backend

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # macOS/Linux

pip install -r requirements.txt
```

Create a `.env` file inside `backend/` (never commit this file):

```
GEMINI_API_KEY=your_key_here
RESEND_API_KEY=your_key_here   # optional, only needed for the email-report feature
```

Run the API server:

```bash
uvicorn main:app --reload --port 8000
```

Interactive API docs will be available at `http://localhost:8000/docs`.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

The app will be available at the URL Vite prints (typically `http://localhost:5173`), and it expects the backend running at `http://localhost:8000`.
